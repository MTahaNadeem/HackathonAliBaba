# CourseCompass Ai: complete product build brief

Build CourseCompass Ai, a beautifully designed, accessible career and learning navigator for students in Pakistan. This is a real application with a production PostgreSQL schema and validated server APIs, not a collection of decorative screens. The first release must connect discovering a direction, exploring a degree, finding a university, analysing a job, and following a learning plan. Use only free service tiers. Never enable billing, paid search, paid model fallback, paid job feeds, or automatic upgrades.

## Product promise and audience
Help a student move from uncertainty to an explained choice and a concrete next action. Support Matric, FSc, FA, ICS, ICom, O-levels, A-levels, other equivalence routes, current undergraduate students, and graduates. Do not treat FSc pre-engineering as the default qualification for everyone. Model subjects separately from the qualification system. Include civil engineering, economics, arts/design, business, psychology, computer science, mechanical/electrical engineering, and humanities in the extensible catalogue. Recommendations guide a student's decision; they do not determine admissions or employment outcomes.

Provide three entry points: choose a degree, strengthen skills during a degree, and prepare for a job/internship. Keep one shared profile between journeys. Profile fields include education stage, qualification system, subjects, marks, official equivalence when available, interests, current skills, location, budget, relocation preference, target career and weekly study time. Collect the minimum necessary information. Do not require national IDs, certificate scans, exact home addresses, or sensitive personal information for exploration.

## Architecture
Use React, TypeScript, Next.js App Router conventions, Tailwind and existing shadcn primitives. PostgreSQL hosted by Supabase Free is the sole intended authoritative application database. Use Supabase Auth for accounts. Database ownership is enforced with RLS as well as server authentication. Keep a conventional Next.js build available; Sites may use its Vinext compatibility build for Cloudflare publishing, clearly documenting that hosting adaptation. Avoid making the Sites adapter a database dependency.

Separate catalogue data, pure domain logic, persistence, provider calls, validation and UI. Server Route Handlers expose versionable APIs. Validate every body and use bounded input sizes. Never accept a user-supplied user ID as authority: derive identity from a validated access token. Ordinary user requests use the user's JWT and database RLS, never a service-role bypass. Give errors helpful messages without leaking credentials or personal records.

When credentials are missing, render a useful, clearly labelled guest session with sample role briefs and a deterministic guided adviser. Do not pretend guest changes are cloud-saved. Do not silently replace PostgreSQL with SQLite or localStorage. Offer a downloadable plan; account persistence only succeeds when Supabase is actually connected. Return explicit unavailable responses for unconfigured authentication, rather than fake success.

## Visual direction
Create a working surface whose first viewport lets students act immediately. Palette: midnight #142D52, cobalt #3264D6, mint #CEF3E2, pale blue #EDF3FC, white #FFFFFF, ink #172B48. Use a characterful geometric display face with a calm readable body face; avoid excessive font weights. Typography, spacing and a path diagram should carry the visual identity; avoid stock photos of unrelated students. A generous sidebar, concise top bar, large welcoming headline and asymmetrical content layout establish hierarchy. Signature: a connected path from degree to role to skill, with each node carrying a real action. Secondary surfaces stay quiet. Include subtle motion and respect reduced-motion preferences.

Navigation: My Path, Explore Degrees, Universities, Jobs & Skills, My Learning, Profile. Make a contextual adviser accessible across every view. Use a mobile drawer rather than squeezing six tiny tabs into a bottom bar. Preserve keyboard focus, labels, readable contrast, clear selected states, 44px targets and visible errors. Use real dialogs/sheets for modals, matching available shadcn components. Every visible action must work or explain the exact missing prerequisite. No fake unread notifications, fabricated placement rates, invented testimonials or arbitrary AI confidence percentages.

## Dashboard
Show the student's next action, chosen direction, a compact path map, suggested paths and learning progress derived from real session/account state. Before onboarding, invite them to personalise the path. Clearly label example content. Actions navigate to relevant views, start profile editing or select a goal. Progress is calculated from completed milestones, not a decorative fixed number.

## Degree discovery
Search and filter by discipline. Each path contains a title, plain-language description, activities, subjects, sample careers, transferable skills, practical trial task and caveats. Recommend multiple options using a transparent interest/subject matching function. Show the factors behind the ordering. Let users compare up to three paths and choose one as a goal. A student can change goals without losing the profile. Avoid numerical personality destiny scores.

## University discovery
Represent each institution at campus/programme level. Include official source links, city, public/private status and verification state. Store admission cycles separately, along with source date, subject requirements, academic minimums, test requirements, aggregate formula, fee period, mandatory charges and historical closing merit with year/category.

Apply hard eligibility checks only when source-backed rules and necessary student inputs exist. Marks alone are insufficient. For O/A-level students use official IBCC equivalence if provided; do not invent grade conversion tables. O-level-only students need a higher-secondary pathway before an undergraduate admission assessment. Missing equivalence/test scores produce 'needs information'. Unknown fees must not be counted as within budget. Unknown rules must not produce 'eligible'. If a university has not supplied current verified admission data, show 'check current admissions' and an official link, rather than inventing cutoffs. Budget comparisons use matching fee periods. Distance is approximate or city-based unless an actual routing source is integrated.

Rank results based on explicit student preferences. 'Best' means suitable and feasible for that student, never a universal unsupported league table. Explain why each option is shown. Show recognition/accreditation as unverified unless checked at the appropriate programme/campus level.

## Jobs and skill analysis
Provide searchable, clearly labelled example role briefs across several disciplines. Do not present samples as live vacancies or add fake employer brands. Support pasted job descriptions as a first-class feature. Extract and retain requirement evidence from the supplied text. Separate skills, degree requirements, experience, licences and optional preferences. Compare requirements to user-stated skills and evidence. Say 'not yet demonstrated' instead of assuming absence. A learning plan does not waive formal eligibility requirements.

Use deterministic skill matching for the no-key experience and label its limitations. Handle aliases and word boundaries, avoid matching 'R' inside unrelated words, and treat negated requirements carefully. No extractable skills should result in a helpful request for a fuller description, not fabricated gaps. Do not scrape LinkedIn. Future feeds require verified country coverage and permission. Real opportunities need source, timestamp, expiry and external apply URL.

## Learning plans
Each task connects target skill, free resource, practice assignment and evidence to save. Resource records contain provider, topic, URL, language, format and access label. Distinguish free content, preview-only and paid certificates. The initial catalogue uses checked official resource hubs; do not invent deep course links. Filter by field, format and available time. Generate a sequenced plan with prerequisites, realistic adjustable weekly hours, completion checkboxes and accessible progress. Download the plan as Markdown. Provide empty states when no plan exists. Save progress to PostgreSQL for authenticated users and show whether it is saved or only present in the guest session.

## Adviser
Use Gemini's free developer tier only when a key is configured on a project with no billing and user consent is given for the relevant message/context. Free-tier data policies differ from paid services: do not send resumes, names, emails, grades or sensitive documents by default. Send only minimal selected goal/skill context. Keep the model name configurable. Use timeouts, input bounds, per-user quotas and no automatic paid fallback. On provider failure return an explicitly labelled guided response. Never represent deterministic logic as a live LLM.

The adviser can explain paths, suggest catalogue resources and structure a plan. Ground facts in supplied catalogue records and provide source IDs. It must not invent admissions deadlines, salaries, placements, fees or employment guarantees. User text and imported listings are untrusted data, not instructions to change system policy or call arbitrary URLs. Return plain text and safely render it; never execute model-generated HTML. The save-plan action is deterministic and visible to the student.

## APIs and persistence
Implement health/configuration reporting without secrets, profile GET/PUT, catalogue reads, recommendations, university filtering, job analysis, plan creation/update and chat. Store user profiles, plans and milestones with ownership policies. Use a JSON profile column for a versioned profile payload where useful but keep ownership and timestamps typed. Include normalized catalogue schema for degrees, careers, skills, resources, universities, campuses, programmes, admissions and job requirements. Include migrations and a documented seed workflow. Do not expose database errors directly.

## Authentication
Provide email/password sign-in and sign-up when Supabase is configured, account confirmation instructions, sign-out and authenticated data reload. Validate sessions server-side. Never log passwords or tokens. Supabase browser auth storage may retain the session token; it is not a substitute for authoritative database records. Reset/account deletion must either be implemented securely or remain explicitly outside this release, without dead controls.

## Validation and delivery
Run TypeScript and production builds. Add meaningful tests for eligibility edge cases, missing equivalence, unknown fees, word-boundary skill extraction, negation, plan structure, profile validation and authentication failures. Probe the real server for routes and error cases. Browser interaction testing only when requested by the user. Include SETUP.md, .env.example, SQL migrations, README, architecture notes, seed workflow, and a three-minute demo script. Document what actually runs versus what needs user credentials. Keep secret files, node_modules and build outputs out of Git. Push complete source to the user's AliBabaHackathon repository, preserving existing work. Privately publish through Sites if available, and also retain the conventional Next.js deployment path. Do not claim to win the hackathon, be production certified, or have verified services that were not tested.

## Completion criteria
The application has a coherent excellent interface; all six views and adviser work; profile inputs change suggestions; degree comparison works; university filters explain unknowns; pasted jobs produce explainable skill gaps; a goal becomes a usable plan; progress updates; export works; authentication and PostgreSQL code are complete and ready for supplied free credentials; the built artifact and source are delivered; missing external configuration is clearly reported. Keep improving actual blockers until completed, rather than ending after writing this prompt.
